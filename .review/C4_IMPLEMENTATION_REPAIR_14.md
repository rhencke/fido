## 1. The defect

`elaborate_indexed` constructs one exact causal chain — `CompilationInput` → `ExpressionPhase` →
`ExprWorkForest` + `ExprWorkIndex` → `TypeNameFactTable` → `ForestOutcomeTable` + `OutcomeTrace` →
`AnnotatedExprWorkForest` → `ForestExprFactTable` → `ExpressionDiagnostics` — and then **discards it**.

On success `ElaborationFacts` retains selected projections. `CompilableProgram` retains `cp_program`,
`cp_index`, `cp_facts`, and `cp_prov : elaborate cp_program = …`. That equality is in `Prop`, is erased, and its
right-hand side contains only the already-stripped result: it is not the causal object and cannot project it.
The present "object identity" theorems expose the loss by *rebuilding* — calling `build_compilation_input` and
`build_expression_phase` again and proving the stored projections equal independently recomputed ones. On
failure, `ElaborationFailed` / `CompileFailure` retain only a flattened diagnostic list.

This is the rejected provenance pattern at the final boundary: build the exact object → discard it → retain
selected outputs → rerun the builders → use equality as provenance. Future `SafeProgram` proofs and user
extensions cannot consume the accepted C4 causal object; they must reconstruct it. **No green proof or test
command can repair a constructor topology that does not retain the object.**

Repair 13 is correct and stays: one immutable source authority, one retained `CompilationInput`, one
proof-carrying `ExprWorkForest`, the exact standard-map-backed `ExprWorkIndex` built once, no production
`List.find` key lookup, exact `WorkMember`/`SuffixMember`/`ConversionWork`/`ConversionStep` identity, one
`OutcomeAccumulator` and intrinsic `OutcomeTrace`, exact final-to-tail causal preservation, one dependent
`ExpressionPhase`, exact source `TypeSyntax`/operand identity, exact diagnostic identity, one `convert_const`,
unchanged generated bytes, no C5.

## 2. Required whole-elaboration object

Create one exact proof-carrying object; a suitable shape is:

```coq
Record ElaborationCore (p : GoProgram) (ip : IndexedProgram p) : Type := {
  ec_input : CompilationInput p;
  ec_phase : ExpressionPhase ec_input;
  ec_package_refs : PackageMap (list DeclRef);    ec_package_present : exact domain proof;
  ec_package_len : exact bucket-length proof;     ec_package_belongs : exact membership proof;
  ec_root_layout : PackageMap FreshRootEntryKind; ec_root_layout_ok : exact source/layout proof;
  ec_build_plan : FreshBuildDisposition;          ec_build_plan_ok : exact plan proof;
  ec_raw_diags : list DiagnosticReason;           ec_raw_diags_exact : exact projection from phase + package refs;
  ec_diags : list DiagnosticReason;               ec_diags_exact : exact command ordering / plan projection

```

Prefer indexing `ElaborationCore` directly by the exact `CompilationInput` or `IndexedProgram` so coherence is
definitional and foreign pairing is impossible.

Rules: build the input once; build the phase once from that exact input; build package buckets once from the
retained visit; build layout and plan once; derive raw and final diagnostics from those exact stored objects. No
copied peer table, no independently rediscovered domain, no second AST, no foreign phase/map/layout/plan
pairing, and **no equality to a second builder as internal provenance**. Build it once: `build_elaboration_core`.

## 3. Result constructor topology

Index the decision by the exact core:

```coq
Inductive ElaborationDecision {p ip} (core : ElaborationCore p ip) : Type :=
| ElaborationAccepted (Hnil : ec_diags core = nil) (Hvalid : SourceProgramValid p)
                      (Hpreflight : fresh_build_preflight_ok p)
| ElaborationRejected (Hne : ec_diags core <> nil).

Record ProgramElaboration (p : GoProgram) : Type := {
  pe_indexed : IndexedProgram p; pe_core : ElaborationCore p pe_indexed;
  pe_decision : ElaborationDecision pe_core }.
```

Equivalent smaller shapes are allowed. Required: one exact core survives both branches; the decision is indexed
by that core; success and failure cannot substitute an equal recomputed core; `pe_input`, `pe_phase`,
`pe_diags`, `pe_layout`, `pe_plan` are projections; no separate result record of stripped copies; no equality
proof is needed to recover core data.
