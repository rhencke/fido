## Accepted claim

M2 delivers one small diagnostic timing aid: `make perf`, which runs the exact `make -j1 check` path once
project-cold and once hot on a dedicated serial builder, records cumulative elapsed milliseconds at nine real
target completions, and replaces one tracked `.review/PERFORMANCE.tsv`. `git diff` is the comparison.

Timing is diagnostic evidence. It is not certified correctness, not a semantic authority, not a benchmark
framework and not an acceptance gate: no gate consults it and nothing depends on it.

M2 measures and reports. It does not optimize, restructure, split proof modules, reshape the build graph, or
implement any recommendation it produces.

## Blocking defect classes

The first candidate was blocked on measurement truth rather than on shape. These classes are stated first
because they are the ones that were missed: a label that does not describe the executed state, a summary that
pools unlike samples, and a coverage claim wider than what ran.

- a scenario or cache label that does not describe the state the command actually ran in;
- a cold sample that followed another measured project command in the same cache namespace;
- `cache_after` copied from `cache_before` rather than observed;
- one cache authority asked to state two different facts at once;
- a cache state the runner cannot establish;
- a reused cache naming a run but not the exact prime sample, source, suite, builder and namespace;
- repeated identical incremental edits, so later samples are exact cache hits under an incremental label;
- a summary that omits edit identity or derived parent context, pooling unlike samples into one median;
- a selected derived child reported as support;
- a command measured once standing in for a scenario it never ran;
- a raw-log path that two samples share, or a retained digest whose file is absent;
- a disposable source taken from a different source view than the observation subject;
- environment identity read from a builder that did not perform the work;
- a cumulative resource high-water mark attributed to one sample;
- a wall-clock duration presented as monotonic, or aggregate step work presented as elapsed time;
- zero recorded as a duration where work occurred;
- a comparison verdict from stored summaries that were never recomputed;
- two observations compared across a changed scenario, edit, parent or concurrency definition;
- a selector model that differs between run and comparison modes;
- a cancelled run leaving no inspectable bundle, or a run identity that can collide;
- two registry fields stating one fact, or a required field nothing consumes.


- a public Make target, anchored pre-commit stage, or Docker stage with no registry classification;
- a registry entry naming a target, stage or anchor that no longer exists;
- a command, scenario, cache state or observation identified by line number or list position;
- a partial or selective run that records, or claims full-suite coverage;
- a cached sample without its exact prime run and cache identity, or an unknown cache labelled primed;
- an incremental edit applied to the real working tree, or not restored byte-exactly;
- a failed, incomplete or cancelled suite reported as a result rather than as an incomplete run;
- an average stored in place of the retained samples, or a summary the validator cannot recompute;
- incompatible observations compared as ordinary percentage deltas, or a hidden fixed noise threshold;
- instrumentation that changes command order, bytes, output, exit status or side effects;
- normal Make or hook behaviour that differs when observation is disabled;
- a skipped or vacuous control counted as passed;
- any proof, theorem surface, extraction, transport, generated byte, golden or runtime change;
- an optimization implemented under M2, or M3, M4, C5 Step 0 or C5 work begun early.

## Required evidence

- one registry whose closure is authoritative, with its digest stored in every observation;
- the permanent command-surface validator running in `make check` and the staged hook, with load-bearing controls;
- deterministic self-test fixtures that need neither Docker nor Rocq, and mutation checks proving each root rule
  load-bearing by deleting its effect and watching its own named controls fail;
- one canonical observation recorded from a clean, complete run against one exact committed ref;
- per-module timing, the Dune adjacency, the critical path and downstream rebuild sets from the pinned toolchain;
- Git history analysis over the exact accepted range, reported with and without the M1 source-diet campaign;
- one machine-readable and one plain comparison against a Git ref and a local path;
- full proof, assumption, extraction, transport, e2e, regeneration, publication and generated-byte checks unchanged.
